# IRON & SKY: инструкция для нейросети-разработчика

Браузерный 3D танковый бой: ангар, покупка танков за серебро, зоны бронирования, баллистика, боты, босс, режим бомбардировки. Управление с ПК и телефона. Папка и репозиторий называются WarThunder, название игры — **IRON & SKY**.

Этот файл составлен по части кода. Если он расходится с кодом, прав код: проверь и обнови файл.

## 1. Как работать с владельцем проекта

- Общайся по-русски, коротко и по делу.
- Делай только то, что попросили. Не переписывай соседний код и не меняй баланс «заодно».
- Заметил другой баг — сообщи, но без спроса не чини.
- Не говори «готово» или «проверено», если не запускал проверку. Прямо пиши, что не проверено.
- Перед изменением прочитай файл и найди все места использования. Не угадывай имена функций и ключей.
- Удаление файлов, крупный рефакторинг, новые зависимости и push — только с согласия. Push в `main` запускает деплой на GitHub Pages.

## 2. Стек и команды

TypeScript, Three.js, Vite, React 19 (только как HTML-оболочка), Tailwind 4 плагин и свой `src/index.css`.

| Задача | Команда |
|---|---|
| Установка | `npm install --legacy-peer-deps` (так делает CI, Node 22) |
| Dev-сервер | `npm run dev` (порт 3000) |
| Проверка типов | `npm run lint` (это `tsc --noEmit`) |
| Сборка | `npm run build` |
| Тесты | `npx tsx --test src/game/*.test.ts` |

- Скрипта `test` в `package.json` нет. Тесты написаны на `node:test` и `node:assert/strict`.
- В репозитории два lock-файла: `package-lock.json` и `bun.lock`. Меняя зависимости, помни об обоих.
- CI тесты и проверку типов **не запускает**, только сборку. Запускай их сам.
- Прогони тесты и `lint` до изменений, чтобы отличать старые ошибки от своих.
- Возможная ловушка: `i18n.test.ts` берёт путь через `new URL(import.meta.url).pathname`. Если в пути к проекту есть кириллица или пробелы, он будет percent-encoded, и тест, читающий `src/`, может упасть с `ENOENT`. Это не ошибка локализации; надёжное исправление — `fileURLToPath`.

## 3. Архитектура

`src/main.tsx` → `App.tsx` → `initGame(mountEl)` из `src/game/engine.ts`. `initGame` возвращает функцию очистки.

- `App.tsx` — статическая разметка HUD и меню. React-состояния нет. Движок ищет элементы по `id` и меняет DOM напрямую.
- Не переименовывай и не удаляй `id` и `data-testid`, не проверив `src/` целиком.
- Не переводи UI на React state, если об этом не просили: React и движок начнут перезаписывать друг друга.
- `engine.ts` (около 4500 строк) — игровой цикл `stepFrame`, состояния (меню, бой, пауза, конец матча, бенчмарк), камера, ввод, HUD, матчи.
- Для отладки в консоли браузера есть `window.IRONSKY` (танки, боты, сцена, мир, настройки, состояние).

| Область | Файлы в `src/game/` |
|---|---|
| Танк: модель, движение, башня | `tank.ts`, `trackAssembly.ts` |
| Характеристики танков | `tanks.ts` |
| Урон, снаряды, коллизии | `damage.ts`, `ballistics.ts`, `collision.ts`, `envCollision.ts` |
| Оружие и способности | `machineGun.ts`, `aps.ts`, `abilities.ts`, `flamethrower.ts` |
| ИИ | `bots.ts`, `botTactics.ts`, `boss.ts`, `playerSkill.ts` |
| Режимы, деньги, история | `modes.ts`, `economy.ts`, `matchHistory.ts` |
| Карты | `world.ts` (hills), `city.ts` (city), `london.ts` (london) |
| Бомбардировка | `bombardment.ts`, `airRaidConfig.ts` |
| Меню и ангар | `menuStage.ts`, `menuOrbit.ts`, `hangarStage.ts` |
| Интерфейс и ввод | `ui.ts`, `i18n.ts`, `settings.ts`, `touchControls.ts`, `hitcam.ts`, `minimap.ts`, `console.ts`, `cheats.ts` |
| Прочее | `audio.ts`, `benchmark.ts`, `visibility.ts` |

Большие файлы (`tank.ts`, `engine.ts`, `i18n.ts`, `london.ts`, `ballistics.ts`) читай по частям через поиск и правь точечно. Не перезаписывай их целиком: легко молча потерять код.

Новую логику по возможности выноси в отдельный модуль с чистыми функциями (без DOM и WebGL) и добавляй рядом `*.test.ts`. Не раздувай `engine.ts`.

## 4. Обязательные правила

### Локализация: ru, sr (латиница), en
- Новый текст интерфейса добавляй ключом **во все три словаря** и выводи через `t('key')`. Наборы ключей должны совпадать.
- Тест ищет только вызовы с литералом `t('...')`. Динамически собранные ключи проверяй сам.
- Проверь начальный русский текст в `App.tsx` и его замену при смене языка.
- Не переводятся: `IRON & SKY`, кнопка `Язык/Language/Jezik`, названия карточек языков, названия моделей танков.
- Названия и описания танков, режимов и карт локализуются в `i18n.ts`. Канонические `name` в `tanks.ts` и `modes.ts` проверяются тестами.
- Подписи клавиш лежат отдельно, в `settings.ts` (`getKeyLabels`, `keyName`). Часть сообщений (например, в `cheats.ts` и `economy.ts`) задана по-русски прямо в коде: проверь, как они доходят до игрока.

### Сохранения игроков (`localStorage`)
- Ключи вида `ironsky.*.vN` (серебро, купленные танки, выбранный танк, настройки и др.). Не переименовывай их и не меняй формат без миграции: пропадёт прогресс.
- Доступ к хранилищу оборачивай в `try/catch`. Модули должны импортироваться в Node, где нет `window`.
- Новую настройку добавляй в `GameSettings` и `DEFAULTS`. `resetSettings` сохраняет язык и тип управления.

### Режимы и читы
- Режимы описаны в `GAME_MODES` (`modes.ts`): `tdm100`, `rounds5v5`, `training`, `juggernaut`, `dead`, `bombardment`.
- Читы разрешены **только** в `training`. Не обходи `allowCheats`, `canRunConsoleCommand` и `enforceCheatsOff`.
- Карта `london` связана с режимом `bombardment`. Выбор карты и режима согласуют функции `resolveMapAndMode...` из `bombardment.ts`.

### Баланс
- Цены, урон, броня и награды закреплены тестами. Меняй их только по просьбе.
- Если баланс изменён намеренно, обнови тест и описания (включая тексты наград в трёх языках). Не подгоняй и не отключай тесты ради «зелёного» прогона.
- Локальные оси: `+Z` вперёд, `+X` влево, `+Y` вверх. Углы в расчётах — в радианах (в `HitResolution.angleDeg` — в градусах).

### Производительность и ресурсы
- В покадровом коде избегай лишних `new Vector3`, массивов, замыканий и поиска по DOM.
- Геометрии, материалы, текстуры и render target, созданные динамически, освобождай через `dispose()`. Общие (разделяемые) ресурсы не освобождай, пока они используются.
- Каждый новый обработчик событий и таймер снимай в функции очистки `initGame`.
- Сохраняй упрощённый путь для программного WebGL (`isSoftwareGl`), LOD и отсечение из `visibility.ts`.
- `dt` в цикле ограничен 0.05 и умножается на `timeScale`. Движение считай через `dt`, а не по кадрам.

### Карты
- `hills` симметрична относительно `z = 0` (рельеф, спавны, цели). Это проверяет `world.test.ts`.
- При смене карты вызывается `world.dispose()`, а ссылка на мир обновляется в танках, ботах, баллистике, боссе и миникарте (`loadMap`). Новый объект, зависящий от мира, добавь туда же.

### Интерфейс
- Любую функцию управления проверяй и для клавиатуры с мышью, и для сенсора.
- В пользовательские строки, вставляемые через `innerHTML`, не подставляй непроверенные данные (из консоли, `localStorage`, URL).

### Конфигурация и секреты
- В `vite.config.ts` не трогай логику `base` без причины (нужна для GitHub Pages), плагин копирования `src/assets` и настройки `DISABLE_HMR` (в коде есть комментарии с запретом).
- Пути к ресурсам должны работать с `base` вида `/repo/`.
- Не коммить `.env` и ключи. Это клиентская игра: всё, что попадает в бандл, видно игрокам, включая любой API-ключ.

## 5. Чек-листы

### Новый танк
1. `tanks.ts`: полный `TankSpec` в каталоге (порядок влияет на тест названий).
2. `tank.ts`: модель и камуфляж; `trackAssembly.ts` и вызов построения гусениц.
3. `ballistics.ts`: хитбоксы и топливные баки (`getFuelBoxesForTank`).
4. `i18n.ts`: `role`, `country`, `gunName`, `description`, `mgName` на трёх языках.
5. Тесты: цены (`economy.test.ts`), названия (`i18n.test.ts`), подвеска (`trackAssembly.test.ts`).
6. Найди поиском ID похожего танка по всему `src/`: там могут быть особые случаи (например, в `damage.ts`).
7. Проверь ангар, меню, бой, миникарту, hitcam и ботов.

### Новый режим
1. `GAME_MODES` и, если нужно, логика оценки исхода в `modes.ts`.
2. Тексты в `i18n.ts` на трёх языках.
3. Поддержка в `engine.ts`: состав команд, HUD, конец матча, награда, история.
4. В `economy.test.ts` проверяется точное число режимов.

### Новая карта
1. Модуль, реализующий `GameWorld`, включая `dispose()`.
2. Запись в `MAPS` в `engine.ts` и тексты на трёх языках.
3. Проверь спавны, коллизии, навигацию ботов, миникарту и повторную смену карт.

## 6. Перед сдачей работы

1. `npm run lint`
2. `npx tsx --test src/game/*.test.ts`
3. `npm run build`
4. Запусти игру и проверь затронутое: меню → бой → пауза → меню → новый бой. Посмотри консоль браузера. Тесты не заменяют проверку графики и управления.
5. В отчёте напиши: что изменено, в каких файлах, что запускалось и с каким результатом, что осталось непроверенным.

## 7. Прочее

- `public/assets/aistudio/` содержит картинки и JS/HTML-файлы с хешами в именах. Это не исходники из `src/`: не правь их вместо исходников и не удаляй, не проверив ссылки и не спросив.
- Титры и пасхалки (например, выстрел в небо, фраза над кнопкой «ИГРАТЬ») — намеренные. Не удаляй и не «исправляй» их тексты без просьбы; титры проверяются тестом.
